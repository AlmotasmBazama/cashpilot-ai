# تدقيق خصوصية النشر العام

التاريخ: `2026-11-14` — المنطقة: `Africa/Tripoli`.

## القرار

النشر المقترح هو **لقطة مصدر نظيفة في مستودع نشر منفصل**، مع إبقاء المستودع
المحلي وتاريخه كما هما. يستخدم الالتزام الجديد عنوان GitHub `noreply` المرتبط
بالحساب المتحقق منه. لا تُنقل مراجع الأدوات المحلية أو ملفات اللقطات أو الأسرار.

هذا القرار يخص خصوصية النشر؛ لا يُعد تصريحًا بجاهزية إصدار المتجر أو ضمانًا
بخلو المشروع من كل عيب أمني.

## النطاق والمنهج

- فُحصت الملفات المتعقبة والملفات الجديدة غير المتجاهلة باستخدام أنماط مفاتيح
  المزودين، رموز GitHub، المفاتيح الخاصة، Google refresh/client secrets، AWS،
  JWT، كلمات مرور نصية، البريد، أرقام الهاتف، ومعرفات الملكية.
- عند أخذ العينة، شمل فحص الحالة الحالية **1,681** مسارًا، منها **1,619** ملفًا
  نصيًا. هذه أعداد العينة أثناء العمل وليست جردًا ثابتًا للإصدار النهائي.
- شمل الفحص كل المراجع المحلية القابلة للوصول: **2,903** كائنات Git، منها
  **1,913** نسخة ملف نصي. وفُحصت بيانات مؤلف/منفذ الالتزامات أيضًا.
- استُبعدت المواد الثنائية من تحليل النص، مع مراجعة مساراتها وأنواعها. لا
  يمثل هذا الفحص مراجعة بصرية شاملة لكل أصل ثنائي.
- اقتصرت مخرجات التدقيق على المسارات والفئات والأعداد؛ لم تُطبع قيم الأسرار
  أو البريد الشخصي. بقيت أدوات التدقيق ونتائجها التفصيلية محليًا تحت `build/`.

## النتائج

1. **بيانات الالتزامات:** تضم الالتزامات التاريخية عنوان بريد شخصيًا على نطاق
   استهلاكي، وليس عنوان GitHub `noreply`. لذلك فإن رفع الفرع بتاريخه سيكشفه،
   حتى إن كانت ملفات المصدر نفسها خالية منه.
2. **المراجع المحلية:** وُجدت 30 لقطة واجهة/ملف XML في مرجع التقاط محلي تابع
   للأداة. ليست هذه المواد ضمن تاريخ `HEAD`، لكن رفع كل المراجع أو استخدام
   `--mirror` قد ينشرها. لا تستخدم هذين الأسلوبين للنشر.
3. **الحالة الحالية:** لم يكشف الفحص النصي عن مفتاح Groq/GitHub أو مفتاح خاص
   أو JWT أو رمز Google refresh قابل للاشتباه. المطابقات الشبيهة بالمفاتيح
   في ملفات إعداد Firebase هي إعدادات عميل عامة، وليست حساب خدمة أو اعتماد
   خادم. تبقى قيود API وAuth وFirestore وApp Check مطلوبة خارج المستودع.
4. **المطابقات الأخرى:** تركزت مطابقات البريد في أسماء أصول Apple ذات
   الصيغة `@2x.png` وجردها؛ وتطابقت كلمات مرور/هواتف/معرفات أخرى مع fixtures
   اختبارات أو أسماء دوال ومسارات. لم يُكتشف بريد استهلاكي في نصوص المصدر
   المرشحة للنشر؛ الاستثناء المؤكد موجود في بيانات Git التاريخية.
5. **الملفات المحلية:** أضيفت قواعد تجاهل محددة تحت مجلدات QA التالية لمنع
   إدراج صور PNG/JPEG/WebP وملفات XML دون مراجعة مستقلة:
   - `docs/qa/ai_compact_confirmation/`
   - `docs/qa/ai_preview_flow/`
   - `docs/qa/home_expense_analytics/`
   احتُفظ بالملفات محليًا ولم تُحذف. شملت العينة 29 صورة PNG وملف XML واحدًا.
   أضيفت أيضًا أنماط تجاهل لأسماء ملفات service-account وFirebase Admin SDK
   الشائعة، مع إبقاء إعدادات عميل Firebase اللازمة للبناء.

## التحقق قبل الرفع

- نجح `git check-ignore` لعينات الصور وملف XML في المجلدات الثلاثة.
- يجب أن يُنشأ مستودع النشر من فهرس المصدر المراجع، دون نسخ `.git` أو
  المجلدات المتجاهلة أو بيانات الجهاز، ثم يُعاد فحص فهرسه قبل الرفع.
- تُراجع هوية الالتزام الجديد وعنوان `noreply`، ويُرفع فرع النشر المحدد فقط.
- قواعد `.gitignore` لا تزيل الملفات التي سبق تعقبها ولا تمحو التاريخ؛ سبب
  اختيار اللقطة المنفصلة هو الحفاظ على الأصل المحلي مع تجنب نشر بياناته
  التاريخية غير اللازمة للعرض العام.

الفحص آلي ومحدود بالأنماط والمواد المراجعة. لا يُغني عن مراجعة تغييرات لاحقة
أو عن تدوير أي اعتماد يُكتشف تسربه مستقبلًا.
