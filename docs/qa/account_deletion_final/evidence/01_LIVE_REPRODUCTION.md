# دليل إعادة الإنتاج الحي المنزوع الحساسية

## التسلسل

1. إنشاء حسابات اصطناعية جديدة وعدم إعادة استخدام حساب محذوف أو محجور.
2. تسجيل الدخول إلى هدف الحذف وتشغيل واجهة الحذف الحقيقية.
3. نجاح إعادة المصادقة وتفعيل سياج النسخ والكتابة.
4. آخر نقطة ناجحة: `writersVerified`.
5. فشل أول اتصال حذف عودي قبل `cloudDeleted`.
6. قبل الإصلاح: `data_deletion_cloud_failed`.
7. بعد إصلاح النقل وإعادة فتح التطبيق نفسه: `providerUnavailable`.
8. النتيجة: عملية واحدة محتفظ بها في الحجر؛ صفر استمرار إلى المحلي أو Auth.

## فحص المسار

فحص Android مستقل للعنوان المنشور، بلا اعتماد، أعاد:

`status=401 code=unauthenticated`

وهذا يثبت وجود route ويرفض تفسير 404. لم يُخزن الطلب أو Token أو معرف حساب.

## حدود الاستنتاج

المصدر المنشور يحول أخطاء مخزن الحذف العودي غير المتوقعة أو عدم اكتمال إثبات الفراغ إلى `providerUnavailable`. كما أن استئناف `/auth` أعاد الرمز نفسه. التقاطع هو تبعية Admin للحذف/التحقق، لكن لا يمكن فصل معاملة القفل عن recursive delete أو قراءات التحقق من دون سجل Cloud Run. لذلك لا تدعي الأدلة دور IAM أو عملية داخلية بعينها.
