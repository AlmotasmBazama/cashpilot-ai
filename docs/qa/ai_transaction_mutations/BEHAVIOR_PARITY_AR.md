# تكافؤ سلوك تعديل العمليات بين الواجهة اليدوية والذكاء

التاريخ: 2026-08-19  
النطاق: تعديل العملية، حذفها/عكسها، والتراجع عن إجراء ذكاء مكتمل.

## النتيجة

مسار الذكاء لا يملك مسار كتابة ماليًا مستقلًا. بعد الحسم المحلي والمعاينة
والتأكيد، يستدعي نفس حالات الاستخدام ومستودع العمليات ومحرك المالية التي
تستخدمها الواجهة اليدوية. لذلك لا توجد كتابة مباشرة إلى `accounts.balance`
ولا تنفيذ مالي صادر من النموذج.

| السلوك | الواجهة اليدوية | مسار الذكاء | نتيجة التكافؤ |
|---|---|---|---|
| تعديل بيانات عملية | `UpdateTransaction` | `UpdateTransaction` بعد أمر محلي typed | مطابق |
| تغيير pending إلى posted أو العكس | `UpdateTransactionStatus`/المستودع | نفس حالة الاستخدام | مطابق |
| حذف دخل/مصروف | `DeleteTransaction` | نفس حالة الاستخدام مع snapshot متوقع | مطابق |
| إلغاء تحويل | دورة حياة زوج التحويل في المستودع | نفس `UpdateTransactionStatus` للزوج | مطابق وذري |
| إعادة عملية محذوفة | `CreateTransaction` | نفس حالة الاستخدام بعد فحص غيابها | مطابق |
| استعادة نسخة قبل التعديل | `UpdateTransaction` | نفس الحالة مع `expectedCurrent` | مطابق |
| حساب الأثر المالي | Finance Engine | Finance Engine | مصدر واحد للحقيقة |
| التحقق من الملكية | جلسة Drift المقيّدة بالمالك | نفس الجلسة، ثم إعادة تحقق عند Confirm | مطابق ومشدّد |

## ثوابت الأثر المالي

- الأموال تبقى `Decimal`/سلاسل عشرية؛ لا يوجد `double` في المسار المالي.
- العملية المعلقة لا تغيّر الرصيد.
- نشر عملية معلقة يطبق أثرها مرة واحدة.
- إعادة posted إلى pending تعكس الأثر مرة واحدة.
- تعديل posted يمر داخل معاملة Drift واحدة: عكس النسخة الحالية ثم تطبيق
  النسخة الجديدة.
- الحذف المكرر، التأكيد المكرر، والتراجع المكرر تُرفض قبل تكرار الأثر.
- مقارنة snapshot تستخدم دقة التخزين الفعلية لوقت SQLite (ثوانٍ) حتى يبقى
  فحص stale صارمًا وقابلًا للاستعادة بعد إعادة التشغيل.

## حدود التكافؤ المقصودة

- تعديل حقول تحويل قائم غير متاح؛ الخدمة اليدوية لا تقدم تعديل زوج تحويل
  مثبت وآمن لكل الحقول، لذلك يفشل الذكاء مغلقًا ويقترح إلغاء الزوج كاملًا.
- إلغاء التحويل يدعم الزوج كاملًا، لكن التراجع عن إلغاء تحويل قائم لا يظهر
  لأن الاستعادة الذرية الآمنة لم تُثبت في الخدمة الحالية.
- التراجع عن **إنشاء** تحويل مدعوم بإلغاء الزوج المنشأ عبر خدمة الزوج نفسها.

## إثباتات الاختبار

- اختبارات Drift/Finance Engine تثبت تحديث posted، الحذف، Undo update، Undo
  delete وUndo create مع الأرصدة الدقيقة وعدم تكرار الأثر.
- اختبارات دورة حياة التحويل تثبت منع تعديل/حذف ساق واحدة وإلغاء الساقين
  ذريًا.
- اختبارات runtime الدائم تثبت stale preview، تبديل المالك، التأكيد المكرر،
  الاستعادة بعد إعادة التشغيل، والتراجع لمرة واحدة.
