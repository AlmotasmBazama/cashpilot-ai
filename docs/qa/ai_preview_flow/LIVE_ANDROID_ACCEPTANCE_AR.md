# قبول Android الحي — المعاينة المالية

## البيئة

- الجهاز: `emulator-5554`.
- Android 17 / API 37 / x86_64.
- تشغيل الواجهة: `flutter run -d emulator-5554 --no-pub`.
- تنفيذ مالي معزول: اختبار integration بملف SQLite مؤقت ومالك اصطناعي.

## القبول المرئي

نجح التحقق من Full Control، وظهور المعاينة مباشرة بلا سؤال تسجيل إضافي،
ووجود زري Cancel/Confirm فقط، وظهور Today وفق `Africa/Tripoli`. نجح الإلغاء
بالإنجليزية والعربية من دون كتابة أو بطاقة خطأ. نجحت بطاقة العربية في RTL،
بما في ذلك ترتيب الزرين والتفاف النص.

صور الدليل موجودة في `screenshots/` بالترتيب من 01 إلى 05.

## القبول المالي المعزول

شُغّل على Android نفسه بمخزن SQLite اصطناعي:

1. الرصيد الابتدائي `100.000 LYD`.
2. Cancel أبقى الرصيد 100 ولم ينشئ معاملة.
3. نُقر Confirm مرتين بسرعة.
4. استُدعي مسار التأكيد مرة واحدة، وسُجلت معاملة Posted واحدة.
5. أصبح الرصيد `95.000 LYD`.
6. أُغلقت القاعدة وأُعيد فتح الملف نفسه.
7. بقي العدد 1 والرصيد 95، ورُفضت إعادة تنفيذ command ID نفسه.
8. حُذف ملف الاختبار المؤقت عند النهاية.

## ملاحظة حالة المحاكي

أداة integration أزالت حزمة الهدف عند teardown، فمسحت تثبيت التطبيق وبياناته
المحلية على هذا المحاكي. أُعيد بناء وتثبيت تطبيق debug الإنتاجي فورًا، وهو
الآن عند onboarding وقد يحتاج تسجيل دخول يدوي. لم يقرأ الاختبار أو يغيّر
Firebase Auth أو Firestore أو أي سجل مالي سحابي. التفاصيل في
`evidence/EMULATOR_STATE_NOTICE.txt`. يجب تخصيص محاكي disposable لأي تشغيل
لاحق لهذا الاختبار.
