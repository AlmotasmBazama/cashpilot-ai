# التراجع الآمن لبوابة Groq

**الحالة:** إجراء جاهز بعد ترويج `00005-civ=100%`. لا يُنفذ إلا عند trigger
فعلي؛ نقطة الرجوع `00002-sww` ما زالت موجودة.

## 1. أهداف التراجع

1. إيقاف أثر Groq على المحادثة النصية بأقل تغيير ممكن.
2. إبقاء الاستجابات المحلية الحتمية متاحة.
3. إبقاء Firebase Authentication وFirebase App Check مفروضين من دون تعطيل أو
   تجاوز.
4. إبقاء فهم صور الإيصالات على Firebase؛ ترحيل Vision ليس ضمن هذا التراجع.
5. إبقاء استخراج الأوامر المالية محليًا/حتميًا، والتنفيذ المالي غير مفعل.
6. حفظ المراجعة الفاشلة والسجلات المنقحة وأدلة التشخيص، وعدم حذف البوابة أو
   مرجع السر أثناء الاستجابة الأولية.

## 2. نقطة الرجوع المعروفة

| الحقل | القيمة أو الحالة |
|---|---|
| الخدمة | `cashpilot-ai-gateway-staging` |
| المنطقة | `europe-west1` |
| المشروع | `cashpilot-ai-a6b49` |
| المراجعة السابقة المحددة | `cashpilot-ai-gateway-staging-00002-sww` |
| مراجعة المرشح | `cashpilot-ai-gateway-staging-00005-civ` |
| وقت نشر المرشح | `2026-08-14T10:55:10.505708Z` |
| وقت بدء التراجع | **بانتظار وقوع إجراء مصرح به** |
| وقت اكتمال التراجع | **بانتظار وقوع إجراء مصرح به** |

وجود اسم المراجعة السابقة لا يغني عن فحصها قبل تحويل الحركة. يجب التأكد من
أنها ما زالت موجودة وأن إعدادها المقصود صالح، من دون قراءة أو تسجيل قيم أي
اعتماد.

## 3. اختيار مسار التراجع

### أ. فشل مرشح `--no-traffic`

إذا فشلت مراجعة المرشح قبل حصولها على حركة افتراضية، فلا يلزم تحويل حركة:

- اترك توزيع الحركة القائم دون تغيير.
- أوقف اختبارات رابط الوسم.
- سجل اسم المرشح والرمز الآمن للفشل ووقت الاختبار فقط.
- لا تحذف المرشح أو سجلاته قبل اكتمال التحليل.
- أصلح السبب في المصدر أو الإعداد، ثم أنشئ مراجعة مرشحة جديدة بلا حركة.

### ب. التراجع من مرشح حصل على حركة

بعد تفويض صريح، أعد 100% من حركة الخدمة إلى المراجعة السابقة المحددة:

```text
gcloud run services update-traffic cashpilot-ai-gateway-staging \
  --project cashpilot-ai-a6b49 \
  --region europe-west1 \
  --to-revisions cashpilot-ai-gateway-staging-00002-sww=100
```

بعد الأمر، اقرأ حالة الخدمة حتى تستقر، وتحقق أن توزيع الحركة الفعلي يشير إلى
المراجعة السابقة. لا تعتبر نجاح الأمر النصي وحده إثباتًا على اكتمال التراجع.

### ج. تعطيل Groq مع إبقاء المحلي

إذا كان الرجوع إلى المراجعة السابقة غير مناسب، فعّل إعداد تطبيق آمن تكون فيه:

- `CASH_PILOT_AI_GROQ_GATEWAY_ENABLED=false`.
- `CASH_PILOT_AI_GROQ_GENERAL_CHAT_ENABLED=false`.
- `CASH_PILOT_AI_GROQ_FINANCIAL_EXPLANATION_ENABLED=false`.
- `CASH_PILOT_AI_GROQ_TOOL_SELECTION_ENABLED=false`.
- `CASH_PILOT_AI_GROQ_ARABIC_SPECIALIST_ENABLED=false`.
- `CASH_PILOT_AI_CURRENT_WEB_ENABLED=false`.
- `CASH_PILOT_AI_FIREBASE_TEXT_FALLBACK_ENABLED=false` ما لم يصدر قرار مستقل
  وصريح بتفعيل fallback مضبوط.

بهذا تبقى التحيات والردود المحلية الحتمية عاملة، ولا يحدث fallback نصي صامت
إلى Firebase يخفي عطل Groq. يظهر فشل الوظيفة البعيدة كخطأ typed قابل لإعادة
المحاولة بدل تكرار رسالة المستخدم. ولأن هذه flags تدخل في تهيئة Flutter، يجب
تطبيق المسار عبر البنية/التوزيع المعتمد فعليًا، لا بافتراض أنها مفتاح ديناميكي
إن لم تكن كذلك.

## 4. ما لا يتغير أثناء التراجع

- لا يُعطل Firebase Auth ولا App Check، ولا تزال البوابة ترفض الطلبات غير
  الموثقة حتى إذا بقيت منشورة بلا حركة تطبيقية.
- لا تُحذف أو تُستبدل تسجيلات App Check الحالية، ومنها تسجيل debug المستخدم
  في قبول Android staging.
- يبقى Receipt Vision على Firebase وبمسار مراجعته الحالي.
- تبقى الأوامر المالية وعمليات تغيير الأرصدة داخل المسار المحلي المحكوم؛ لا
  يُفعّل تنفيذ مالي بالذكاء الاصطناعي.
- لا يُنقل اعتماد Groq إلى Flutter ولا إلى متغير عادي، ولا تُطبع قيمته.
- لا تُحذف خدمة Cloud Run أو المراجعات أو السجلات اللازمة للتحقيق.
- لا يغيّر التراجع مسارات حذف الحساب أو توافق أخطائها القديم.

## 5. محفزات التراجع

- زيادة 5xx أو `groqUpstreamUnavailable` أو timeouts عن حد القبول.
- ارتفاع 429 أو تجاهل `Retry-After` أو حدوث حلقة retries.
- زيادة غير مبررة في رفض Firebase Auth أو App Check.
- انقطاع SSE، تكرار الإجابة، اكتمال فارغ، أو وصول chunks بعد الإلغاء.
- تراجع واضح في جودة العربية أو الإنجليزية أو ظهور أرقام مالية غير مسندة.
- ادعاء تنفيذ إجراء مالي، أو تسرب prompt/response/UID/token/اعتماد في سجل.
- اعتماد نموذج غير متاح أو اختلاف model ID عن الثابت في الخادم.
- فشل cold start أو زمن استجابة يتجاوز الهدف المقاس المعتمد.

## 6. تحقق ما بعد التراجع

1. أكد توزيع الحركة الفعلي أو flags الفعلية بحسب مسار التراجع المختار.
2. افحص `/health` وتأكد من HTTPS و`no-store` وعدم ظهور أي بيانات حساسة.
3. أثبت أن طلبات AI بلا Auth أو بلا App Check ما زالت مرفوضة.
4. اختبر تحية محلية وتأكد أنها تستجيب بلا Groq أو Firebase text.
5. افتح المساعد بعد force-stop وتأكد أن الإعداد الآمن ما زال فعالًا.
6. اختبر رسالة بعيدة واحدة: يجب أن ينتهي loading ويظهر خطأ typed/Retry من
   دون تكرار الرسالة ومن دون fallback نصي صامت.
7. اختبر مسار إيصال اصطناعي وتأكد أن Receipt Vision ما زال مستقلًا على
   Firebase.
8. راجع السجلات الآمنة فقط: request ID والمسار والنموذج/الحالة والمدة والretry
   وrate-limit؛ يمنع حفظ النصوص الخاصة أو UIDs أو الرموز أو قيم الاعتماد.
